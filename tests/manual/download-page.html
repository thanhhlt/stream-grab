StreamGrab download demo

Served by npm run fixtures from localhost (routes: tests/fixtures/download-routes.ts). Every stream is 8 minutes of 4-second segments with ~250 ms latency per request, so a download takes several seconds and its progress, cancel and retry can be watched in the popup's Queue tab. The segments are real H.264/AAC media (FFmpeg's test pattern with a frame counter, and a beep), generated by the bundled FFmpeg.wasm when the server starts. Once a download is complete the task shows Processing while FFmpeg merges video and audio into one MP4, then the file appears in your Downloads folder (e.g. StreamGrab_download_demo_360p.mp4, or … (1).mp4 if that name is taken), under Completed in the popup, and in a notification. It plays in any player: a test pattern with a frame counter and a beep.

Open the StreamGrab popup on this tab: it lists the five streams below (all titled with this page's title; tell them apart by file name). The terminal running npm run fixtures logs manifest requests and every failed request with its Referer.

    Resume and recovery

    Reloading StreamGrab in chrome://extensions has the same effect as restarting the browser: the engine (offscreen document) stops where it is, the session storage holding each task's Referer is cleared, and tasks and stored segments survive. Quitting Chrome completely and starting it again works too.

    1. Download the plain HLS stream. At about a third, reload the extension and open the popup's Queue tab: the task shows Resuming · N / 241 segments already downloaded, then continues from there with (N reused) in its progress line instead of starting again at 0%.
    2. Download the protected stream and reload the extension midway. It fails with The browser (or the extension) restarted since this download began… and its progress line says how many segments it keeps. Reload this page (the player requests the manifest again, with this page as Referer), then press Retry: the download continues from the kept segments.
    3. Download the expiring stream. When it fails, press Retry: it shows the segments it kept, skips them, and fails again where the link "expires". Remove deletes its data; so does Cancel on a running download.
    4. The Queue tab's last line shows the downloaded data and the free disk space. A download stops while less than 256 MB of disk would remain and keeps its segments; free up space, then press Retry (or Retry all failed).
